# AGENTS.md: HV Test project context

Read this before changing anything. It explains what this project is, how it is built, the design system, and why things are the way they are. Keep it up to date: when you make a meaningful change, update the relevant section and add a line to the decision log at the end.

## 1. What this is

**HV Test** is a set of free, browser-only self-assessment tests for personal growth, made by Harsh Goyal (GitHub `harshvittori`). People take a test, get a score, and download personal PDFs. No login, no server, nothing is stored or sent anywhere.

- All Tests page (hub): https://harshvittori.github.io/hv-tests/
- Test 1, **Maturity Assessment** (category **Personal Growth**): https://harshvittori.github.io/hv-tests/tests/maturity-assessment/
- Tagline used everywhere: "Understand yourself. See your patterns. Grow from them."

### Adding a new test (summary, full steps in README.md)

1. Create `tests/<lowercase-slug>/` with `index.html` (copy the Maturity Assessment app as a starting point) and `test.json` (at least `title`; set `category` so it groups on the hub).
2. Add a 1200x630 `og.png` and copy the `og:` / `twitter:` meta tags from the Maturity Assessment page, changing title, description and URLs.
3. Commit to `main`. The workflow rebuilds `tests.json` and the card appears.

`test.json` `status`: `live` (clickable), `coming-soon` (greyed, no link), `hidden` (not listed, URL works), `moved` (redirect folder, not listed). Folders starting with `_` are ignored. Check locally with `node scripts/build-manifest.mjs --check`.

## 5. Design system

### Brand
- Name: **HV Test**. Wordmark "HV TEST" in **Outfit** (Google Fonts, weights 500 to 700): "HV" bold in ink, "TEST" semibold in accent green, letter-spacing 0.04em. Old name was "HV Vault" (fully replaced).
- Logo icon, "Four Options": green rounded tile (rx 12 on a 48 grid) with four answer circles, three white outlines and one filled amber (`#FFC54D`) with a dark tick. It stands for the test itself: pick the option closest to you. Colours are fixed in both themes. SVG is inline in each page; PNGs in `assets/icons/`; favicon is an inline SVG data URI plus a 32px PNG.

### Theme
- **Light by default**, not the OS setting (owner's machine is dark; he wanted light first). A round sun/moon button (`#theme-toggle`, fixed top right) switches; the choice is saved in `localStorage["hv-theme"]` and shared by all pages. `<html data-theme="light">` is set statically and by a tiny head script to avoid flashes.
- Theme switch uses the **View Transitions API** with a circular reveal from the toggle. Do **not** go back to cross-fading colours: that caused the "card blinks" bug (see decision log). Fallback without the API or with reduced motion: instant switch.

### Type and layout
- Headings: serif stack (Iowan Old Style, Palatino, Georgia). Body: system sans. Wordmark and OG images: Outfit.
- Content column max 640px (test) / 880px (hub), 16 to 24px side padding, no horizontal scroll at 390px.
- Rounded corners: cards 10 to 14px, buttons 6px, chips pill.

### Components and motion
- Answer options are cards: hover lifts 1px; selected = green border, soft ring, filled letter circle with a pop, tick on the right. **Selecting updates classes in place; never re-render the quiz on click** (re-render killed the transitions).
- Screen entrance: `#app.enter` fade-rise, only on screen or question changes (class removed after 800ms so in-screen re-renders, like intake chips, don't replay it).
- Progress bar animates from the previous question's value; score bars grow on results.
- All motion is disabled under `prefers-reduced-motion`.
- Intro screen: facts chips (28 to 30 questions, About 10 min, 2 personal PDFs, No login), "Before you start" cards with icons, Start button with arrow, disclaimer under it.
- Hub: category headings (uppercase accent), cards with Live chip, amber bar under "All Tests".

## 6. The Maturity Assessment app

Single file `tests/maturity-assessment/index.html`. Only external scripts: jsPDF 2.5.1 (always), JSZip 3.10.1 and qrcode-generator 1.4.4 (loaded on demand), all from cdnjs.

- Flow: landing, intake (name, age, profession, main focus), quiz, confirm, results.
- Question bank: 104 scenario questions, each option scores dimensions 1 to 5. Each attempt picks 28 to 30 with at least 2 per dimension, shuffles questions and options, and avoids the previous attempt's questions on retake.
- 10 dimensions: Emotional Control, Accountability, Self-Awareness, Handling Conflict, Relationships, Decision-Making, Patience, Empathy, Responsibility, Long-Term Thinking.
- Score: dimension averages mapped to 0 to 100, overall = mean, minus a small response-time adjustment (max 5). Tiers: 0-40 Developing, 41-65 Emerging, 66-85 Grounded, 86-100 Highly Consistent.
- Anti-gaming design: four plausible options, trade-offs, no "correct answer" language. Age and profession are context only, never comparisons.

### PDFs (built client-side with jsPDF)
- **Report** (about 12 pages) and **Plan of Action** (about 10 pages).
- File names: `HV_Test_Maturity_Assessment_Report_<Name>.pdf`, `HV_Test_Maturity_Assessment_Plan_of_Action_<Name>.pdf`; PDF title metadata set.
- **Download both (ZIP)** is the main button: `HV_Test_Maturity_Assessment_<Name>.zip` with both PDFs (two separate automatic downloads get blocked by browsers). Single-PDF buttons stay as secondary.
- Cover: logo mark + "HV TEST" (Outfit, embedded from `assets/fonts/`, Helvetica fallback) and a right-aligned tag "MATURITY ASSESSMENT | REPORT" or "| PLAN OF ACTION".
- Date of assessment shows date **and time** of submission (`assessmentDoneAt`), not download time.
- Every page footer: logo + HV TEST + "Maturity Assessment | <First>'s Report / Plan of Action" + page x of y.
- Last page of both: centred "Keep growing. Take more tests." with a vector QR code and clickable link to the hub, and "Free | No login | Your answers stay on your device".
- Helpers: `drawBrandMark`, `drawCoverBrand`, `drawFooterBrand`, `useBrandFont`, `addMoreTestsPage`, `savePdfDoc`/`saveBlob`, `downloadBothZip`.

### Link previews
Every public page has Open Graph + Twitter tags (title, description, 1200x630 image, url) so WhatsApp and others show a card. WhatsApp caches previews per URL: old messages never update; append `?v=2` to force a fresh preview.

### SEO
- Search target: people searching "HV Test", "Harsh Vittori", "Harsh Vittori HV Test" or the test name should find the site.
- Titles: hub "HV Test by Harsh Vittori | Free Self-Assessment Tests"; tests "<Test> | HV Test by Harsh Vittori". Visible text "HV Test by Harsh Vittori" in the hub footer and under the test's Start button (Google ranks on visible text too).
- `<link rel="canonical">` on every public page; old-URL redirect pages are `noindex` with a canonical to the new URL.
- JSON-LD: hub has WebSite (name HV Test, alternate names) + Person (Harsh Vittori); each test has WebPage with breadcrumb. Add the same block to new tests.
- `sitemap.xml` is generated by `scripts/build-manifest.mjs` (hub + live tests) and committed by the workflow, so new tests are added automatically.
- `robots.txt` is not possible for a GitHub Pages project site (it would have to live at the domain root, in a `harshvittori.github.io` repo). Not needed; submit the sitemap in Search Console instead.
- Google Search Console property (URL prefix `https://harshvittori.github.io/hv-tests/`) must be set up by the owner; verification is the `google-site-verification` meta tag in the hub `<head>` (added 27 Sep 2026). Do not remove it.

## 7. How to verify a change (do this every time)

1. `node scripts/build-manifest.mjs --check`.
2. Serve the repo under `/hv-tests/` locally and drive it with Playwright/Chromium: hub, test landing, intake, full quiz, results, "Download both (ZIP)" and single PDFs. No page errors, no horizontal scroll at 390px, light and dark.
3. Open the PDFs (for example with PyMuPDF): page counts, cover, footer, date with time, closing page; decode the QR (OpenCV) to confirm it points to the hub.
4. Look at screenshots, not just logs.
5. After merging, confirm on the live site that the new build is served, and remind the owner to hard-refresh (Ctrl+Shift+R).

Sandbox note: cdnjs and Google Fonts may be blocked in the build sandbox; route them to local copies from npm (`jspdf`, `jszip`, `qrcode-generator`, `@fontsource/outfit`) during tests.

## 9. Decision log (newest last)

All on 27 Sep 2026 unless noted.

- **Single-app repo became a multi-test hub.** One repo holds every test; `tests/<slug>/test.json` + a generated `tests.json` so new tests appear on the hub automatically.
- **Repo renamed `maturity-assessment` to `hv-tests`** because the URL made the hub look like one test. Old URL kept alive by the separate redirect repo (Pages does not redirect renames).
- **HV Vault to HV Test.** Owner wanted a brand for tests specifically.
- **Logo: "Four Options" icon** chosen from six concepts (owner rejected text-based logos; wanted a symbol). Amber brightened to `#FFC54D` for contrast on green.
- **Colour: sage replaced by emerald + amber spark** for a growth and motivation feel, with a slightly lighter UI overall.
- **Test naming: "Maturity Assessment" is the test, "Personal Growth" is the category.** URL moved to `tests/maturity-assessment/`; `tests/personal-growth/` kept as a redirect.
- **Light by default + toggle** because pages followed the OS dark mode and the owner wanted light first.
- **Options as cards, in-place selection, gentle motion** because the UI felt stiff ("zero smoothness"); the old code re-rendered the whole screen on every click.
- **Wordmark in Outfit** (site and embedded in PDFs) because the default bold sans did not match the rounded icon.
- **Theme blink fix:** colour cross-fade made card background and text pass through the same grey at about 100ms, so text vanished. Replaced with a View Transitions circular reveal.
- **PDF naming and labels** so files from many future tests are easy to tell apart; date now includes time.
- **ZIP download** for both PDFs in one click.
- **Closing PDF page with QR** to bring readers back to more tests.
- **Intro screen polish:** facts chips and icon cards.
- **Link previews (OG tags + images)** because shared WhatsApp links showed no image or description.
- **SEO basics:** titles and visible text with "HV Test by Harsh Vittori", canonical links, JSON-LD, auto-generated sitemap.xml, because searching "Harsh Vittori HV Test" found nothing (site was new and never indexed).
- **This file (AGENTS.md)** added so any AI assistant can pick up the full context; `CLAUDE.md` points here.
